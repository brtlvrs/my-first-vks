# Open items

These surfaced while building this repo out from the `vks-apps`/`vks-platform` patterns and need a decision or verification before they can be called final. See `docs/` for what's already documented.

1. **Per-OS ssh-agent guidance in `docs/02-ssh-keys.md`.** Drafted for macOS/Windows/Linux from general best practice, not from a specific customer's actual fleet — review against what the real target team uses before treating it as final.
2. **VM Service (`apps/hello-vm/`) and vSphere Pods (`apps/hello-vsphere-pod/`) use cases.** Both are wired up as working worked examples — `hello-vm/` now includes the full persistent-data-disk pattern (`/home`/`/root` surviving a redeploy, `vm:*` mise tasks, a demo compose stack) ported from `vks-apps/hoppenbrouwer-ems` — but *when* to reach for either of them over a regular `hello-vks`-style app, and what a realistic, non-toy use case looks like for each, hasn't been discussed yet. Revisit once there's a concrete candidate workload, and expand the docs cookbook with a proper walkthrough chapter at that point (today they only get a short mention in `apps/README.md`/`hello-vm/README.md`, deliberately not a full docs chapter).
3. **Velero backups are an addon, not shipped in `platform/`.** `fzf` is now a hard `[tools]` dependency (was item 1 here) and Velero has been pulled out entirely (was item 3) — it's a real, useful addition to look into for a production setup, but not something this repo provisions by default. See [`docs/11-backups-with-velero.md`](docs/11-backups-with-velero.md) for the shape it would take if/when someone picks this up.
